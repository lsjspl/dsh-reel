# Reel UI 改版方案

目标：让找文件、看内容、返回浏览这三件事清楚且稳定。方案采用两种可交互布局：以目录浏览为主的「清爽文件库」，以及以连续观看为主的「沉浸观看」。建议默认使用清爽文件库。

## 现有界面的主要问题

| 问题 | 改版后的行为 |
| --- | --- |
| 当前/全部/分组、媒体类型、视图、尺寸同时常驻，缺少主次 | 顶部保留类型、搜索和排序；递归范围用有文字的选择器；分组和密度放进显示设置 |
| 排序图标循环切换，用户难以知道下一次是什么 | 直接选择最近修改、名称、时长；显示当前排序 |
| 文件卡片重复堆放类型、后缀、尺寸、时间 | 封面＋名称＋一行必要信息；视频保留时长，详细属性按需展开 |
| 载入期间一直显示旧目录，缺少明确反馈 | 保留内容同时显示正在加载的目标路径；失败提供重试，取消旧请求后不改变当前位置 |
| 播放器操作过多、符号混杂，手机隐藏功能 | 播放、前后文件、时间轴、声音、字幕、倍速常用；其余放进带文字的更多菜单 |
| 页面全屏和浏览器全屏两个按钮难以理解 | 一个常用全屏入口；影院视图作为明确的显示选项；退出按菜单→全屏→播放页处理 |
| 普通观看时滚轮会突然换视频 | 普通播放忽略滚轮和滑动换片；明确进入“刷视频”才启用 |

## 浏览页

- 目录导航和媒体操作分开，当前路径始终明确。搜索框说明当前搜索范围。
- 点击视频进入播放页；返回后恢复目录、搜索、筛选、排序和滚动位置。
- 以同一套线性图标和黑白灰组织界面；浅色主题使用炭黑主按钮，深色主题使用浅灰主按钮，面板和选中背景去掉绿色色调。
- 视频封面以稳定比例展示；图片可切换完整显示。竖屏素材保持原始比例，不通过强制裁切隐藏内容。
- 空目录、没有搜索结果、加载失败分别呈现不同状态；失败提供原地重试。
- 桌面默认显示目录栏；窄屏以目录入口打开抽屉，保留当前位置和全部必要操作。

## 播放页

- 常用控制保持固定位置。桌面空闲时隐藏，暂停、拖动、菜单打开和键盘操作时保持显示。
- 后退 10 秒、播放/暂停、前进 10 秒常驻播放控制栏，手机也可直接点击；前后文件是另一组按钮。
- 时间轴拥有 48px 高的触摸区域和持续可见的滑块。拖动保持原有播放/暂停状态，画面实时寻帧；滑块按屏幕刷新帧合并更新，不受缓冲、时长或窗口更新影响。原生寻帧一次只处理一个目标，完成后取最新位置，避免密集请求让解码一直被取消。
- 转码视频拖动通过轻量 JPEG 帧覆盖主画面，不重启完整转码流；每个客户端最多一条取帧请求，只保留最新目标，半秒粒度缓存；服务端最多两个取帧进程，最长边 640px、缓存上限 8MB，断开请求会终止解码。松手后只重开一次播放流，保留预览画面直到新流可显示，跳转期间保持目标时间。
- 快进按钮轻点前进 10 秒，长按持续 3× 播放（已有倍速超过 1.5× 时按两倍、上限 6×），松手恢复原速；后退按钮轻点后退 10 秒，长按按 3× 速度持续倒退画面，松手停在当前位置。浏览器不支持负播放倍速，后退使用同一条实时寻帧管线；转码格式只在松手时提交一次播放流。鼠标长按画面持续两倍播放。原先暂停的视频可在按住期间观看变化的画面，松手恢复暂停。
- 拖动、快进、后退和跳转期间不在画面中央显示 loading 或 ±10s；持续操作状态放在时间旁。按钮和时间轴不显示点击后的选中框、高亮底色；循环和静音等状态仍通过图标/文字表达。键盘聚焦时间轴可用方向键调整 1 秒、Shift 调整 10 秒、Home/End 到起止位置。
- 转码等待显示明确的准备状态；未知总时长显示未知，不把已接收的片段长度当总长。
- 快速切换时只有当前媒体可以应用续播、自动播放、字幕和错误反馈。
- 普通播放沿用用户的循环、顺序和续播设置；“刷视频”从零起播并默认循环当前短片，浏览短片不会覆盖普通播放的顺序和续播记录。
- 更多菜单采用文字名称，手机和桌面使用相同功能；长菜单允许滚动，触摸目标至少 44px。
- 播放列表按需打开，不挤占初始画面；图片查看保持前后图片导航。
- 读取或解码失败提供持续可见的错误和重试入口，保留返回浏览的路径。

## 已落地的实现

播放器已修复字幕轨道选择、转码字幕偏移、续播记录归属、过期元数据回调、拖动重复转码、转码循环、临时倍速恢复、关闭后的延迟切片、监听器清理、错误编码的一次转码回退及未知时长和缓冲条残留。更多菜单和手机时间显示已接入现有界面，普通窗口滚轮误切片已关闭。

真实浏览页已采用“清爽文件库”：黑白灰底色和主操作、媒体封面、类型标签和紧凑信息；默认打开全部媒体，目录树支持多个硬盘根，布局、递归范围和封面大小收进显示设置。浅色、深色随系统切换。

- 共享后台索引保存文件名、路径、大小和修改时间，搜索可选择当前范围或全部硬盘；多词按 AND 匹配，分页前先匹配完整索引。搜索防抖 110ms，取消旧请求，并校验导航和索引版本，避免过期结果覆盖和错页。
- 首屏先显示直接文件，索引、缩略图和元信息随后补齐。索引由两个遍历任务处理多个根，文件 stat 每批最多 8 个；分组视图仍使用可续扫的目录游标。
- “全部媒体”和手机“媒体库”返回全库概览，清空旧搜索与类型筛选；无索引的后端先显示当前层媒体，再逐页补齐递归扫描结果并显示进度。扫描中断保留已找到的文件，重试会重新读取目录。
- 建索引期间只轮询进度，不反复查询和重画已显示的媒体列表。空列表找到第一批文件后显示一次，索引完成后仅在结果变化时更新一次；结果相同保留卡片 DOM、焦点、滚动位置和预览。
- 切目录时统计只在索引结果返回后提交，不显示临时直接文件数量；索引与普通浏览使用相同的统计格式。索引提示在导航期间保持可见，短暂加载提示延迟 200ms，避免快速读取时闪字；相同文字不重复改写 DOM。
- 视频动态图使用无声 H.264 MP4（最长 4 秒、12fps、最长边 320px），首次需要 FFmpeg 生成，以文件大小、修改时间和生成版本缓存。桌面悬停/键盘聚焦开始；手机滚动停下后只预览最显眼的一张。关闭动态预览、减少动态效果、省流量模式、切后台及进入播放器都会控制解码负担。
- 手机使用可关闭的目录抽屉和底部媒体库/刷视频/目录导航；关闭的抽屉不会进入键盘焦点。视频和图片保持原比例，播放器支持安全区与横竖屏。
- 分组模式每一层都先排子目录分组，再排当前层的独立媒体；点击目录立即选择并浏览，子目录加载不会阻塞导航或在完成后切回旧目录。空目录显示当前标题、路径和空状态，进入有媒体的目录后收起旧空提示。
- “刷视频”只收视频，上下滑动、滚轮或箭头切片；抬手后的合成点击不再误暂停。当前视频就绪后只预读下一条可直接播放视频的 metadata，不提前启动转码。接近播放列表末尾时追加索引页。
- 播放失败保留原因与重试按钮，退出释放播放流、预读视频和动画；已有壁纸视频在观看期间暂停。
- 播放请求在用户点击事件内立即发出，避免手机 Safari 把 metadata 回调中的首次播放当成自动播放拦截；元数据回调仅应用续播和时长，不重复发起播放。

## 性能边界

热搜索查询内存索引，不为每个关键词重新扫描硬盘。服务重启后的索引仍需首次扫描，磁盘唤醒、机械硬盘、远程访问、首次缩略图生成以及不支持格式的转码都存在真实等待时间。索引默认最多 500,000 个文件、64 层目录，约 60 秒到期后按请求刷新；刷新按钮可主动更新，更新期间保留旧索引。达到上限或遇到不可读目录会显示状态，不能据热搜索耗时推断任意媒体都能瞬时起播。

`tests/catalog.mjs` 用两个实际目录和 6,003 个测试文件测量扫描及热搜索，不使用预构造的假列表。当前机器测量约 0.3–0.4 秒扫描、20 次热搜索最慢约 1–3 毫秒；这些是测试环境结果。

## 验证

- `npm test` 覆盖服务端、导航、缓存、完整播放器生命周期；设置 `REEL_FFMPEG` 可执行真实转码和跳转回归。
- `node tests/serve-player.mjs` 启动独立浏览器测试页，自动生成两个目录、横竖屏 MP4、AVI、图片和中英文字幕，运行真实界面和 HTTP 路由。按 Ctrl+C 停止并清理测试文件。
- 真实界面检查桌面、320px/390px 手机和横屏播放，覆盖全库浏览、排序、跨目录搜索、动态图只播放一张、目录抽屉开关、原比例观看、切片和关闭。
- `doc/screenshot/library-desktop.jpg`、`library-mobile.jpg`、`feed-mobile.jpg` 是测试媒体的实际页面截图，彩色画面是 FFmpeg 测试素材。
